Kerberos is an authentication protocol that has three main components:  
1. Principle (Client)
2. Key Distribution Center (Auth server and Ticket granting service)
3. Resource Destination Server (Kerberos enabled service) 

Kerberos has mostly replaced [NTLM](NTLM.md) which was discussed earlier. The general process for Keberos authentication is as follows:

1. Principle communicates with the authentication server. It provides its username and password.
2. The authentication server checks these details against its username and password records. If correct it then generates a ticket GRANTING ticket (TGT) and sends it to the Principle.  
3. The user then provides the TGT to the ticket granting service. The ticket granting service compares the provided TGT from the client to the TGT generated by the authentication server. 
4. If the TGT’s match the ticket granting service generates a SERVICE ticket and gives it to the Principle. The ticket granting service also shares this SERVICE ticket to the Resource Destination server
5. Having now received the Service ticket the principal shares the service ticket to the Resource Destination server. The resource destination server compares the tickets and if correct will allow access to the service for a limited time defined by the service ticket.

## Additional info

- Users and workstations are preregistered in the system with a secret key (often the hash of the password). This secret key will change when the user/workstation changes password for the first time. 
- NTP is used throughout Kerberos protocol to tell when tickets should expire. TGT’s cease to work if there is a time skew between client server and domain controller of 5 minutes.
- Service tickets should expire after around 8-10hrs depending on service.
- User login to keberos security realm event ID is 4768
- Principle doesn’t have secret keys that are used to encrypt tickets
- Keys are stored in the kerb tray which is a non pagable area of memory
