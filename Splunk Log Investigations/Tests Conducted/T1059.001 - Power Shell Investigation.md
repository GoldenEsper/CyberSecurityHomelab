# Obfuscated PowerShell Detection (T1059.001)

> AI Summary
> Investigated and detected obfuscated PowerShell execution using Atomic Red Team test T1059.001. Validated Splunk Universal Forwarder XML field extraction, installed the Splunk Windows Add-On, and built alerts using `eval` and `rex` to parse Sysmon Event ID 1 logs for suspicious flags (`-enc`, `-w hidden`).

## Test Objective

- Observe logs for evidence of malicious use of PowerShell
- Test system setup to confirm correct operation of test environment

## Setup and Troubleshooting

> Splunk XML Extraction Issue
> Initial test was unsuccessful — the Splunk server was not retrieving the correct fields from the XML, making log investigation difficult.

> Mimikatz Execution Blocked
> The Atomic-Invoker failed to run the Mimikatz script due to "Permissions denied".

### Splunk Universal Forwarder Fix

Initially, the Splunk Universal Forwarder `inputs.conf` file was checked for correct configuration, ensuring that the `isXML = True` line is included. Slight modifications to the order of the arguments were made within the file, however the Splunk server was still not processing the XML data.

Following this, the Splunk server was investigated and the Splunk Windows Add-On (which pulls the fields from the XML data) was reinstalled. Upon server reboot after reinstalling the Splunk Windows Add-On, the Splunk server began extracting the fields from the XML data correctly.

### Windows Defender Fix

Investigation into why the Mimikatz script failed to run showed that RealTimeMonitoring was still operating even after being disabled in Windows settings. The following PowerShell command was used to disable RealTimeMonitoring:

```powershell
Set-MpPreference -DisableRealTimeMonitoring $true
```

After this command was run, Mimikatz was able to run after being called upon by Atomic-Invoker. The breakdown of this command is as follows:

- `Set-MpPreference` — [CMDLET](../../Studied%20Ideas%20and%20Concepts/2.%20Powershell%20Investigation/CMDLET's.md) to set configuration settings for Windows Defender
- `DisableRealTimeMonitoring` — parameter
- `$true` — boolean value passed to the parameter, instructing Defender to turn off real-time monitoring

## Test Results

### Test 1: Obfuscated PowerShell via Mimikatz

> Test Detail
> **Method:** Mimikatz.ps1 with `-DumpCreds` flag
> **Test conducted:** 2026-09-10 03:19 AWST (UTC+8)

![Pasted image 20260926184948.png](../../Images/RegularImages/Pasted%20image%2020260926184948.png)

This log shows PowerShell being used to run the malicious script `Mimikatz.ps1` and it uses the parameter `-DumpCreds`, which pulls credentials from LSASS (Local Security Authority Subsystem Service). LSASS runs in memory and enforces security policy, manages passwords, and generates access tokens. It generated a Sysmon EventID 1, which indicates that a new process was created. The command was not obfuscated with `-enc`, which encodes the command in [Base64 Encoding](../../Studied%20Ideas%20and%20Concepts/2.%20Powershell%20Investigation/Base64%20Encoding.md).

> Key Finding
> Sysmon EventID 1 successfully captured the PowerShell invocation of Mimikatz. The command line shows the `-DumpCreds` flag, making detection straightforward when not obfuscated.

## Lessons Learned

- Splunk Universal Forwarder configuration (`isXML = True`) is critical for proper XML field extraction
- The Splunk Windows Add-On must be correctly installed for XML data parsing to work
- Windows Defender RealTimeMonitoring can block attack simulation tools — disable via PowerShell if the UI toggle doesn't take effect
- PowerShell commands without `-enc` or `-w hidden` flags are easier to detect but less realistic
- Obfuscation techniques (`-enc`, `-w hidden`) are used in real attacks and should be the focus of detection tuning
