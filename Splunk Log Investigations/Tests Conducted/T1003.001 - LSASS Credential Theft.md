# Test/s Information and Evidence

## Test One: Dump LSASS.exe Memory using ProcDump

- Details: Memory of [[LSASS]].exe can be dumped for offline credential theft attacks. This can be achieved with [[Sysinterals]] ProcDump
- Command:

```
"#{procdump_exe}" -accepteula -ma lass.exe #{outputfile}
```

## Troubleshooting Test:

*Test 1 Time @GST+8 1416 19/09/2026*
Initially test wouldn't run due to permission issue so set:
```
Set-MpPreference -DisableRealTimeMonitoring $true
```
Then Proc Dump failed to dump the process. This was narrowed down to two potential issues. One being that scripting wasnt enabled in the powershell window so the following command was used:
```
set-executionpolicy remotesigned
```
This did not rectify the issue. The other probable issue was the [[Credential Guard]] tool was enabled which uses [[Privileged Process Integrity]] which would prevent procdump from reading the code. Upon checking the registry it was found to be enabled with [[Safeboot]]. UEFI settings modified to not launch with safeboot.

## Alert Created to detect attack

As this is my first alert created in this project AI was used to assist in creating this rule. Now that the rule has been created.

```
index=endpoint source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventID=10 TargetImage="*\\lsass.exe" NOT (SourceImage IN ("*\\MsMpEng.exe", "*\\taskmgr.exe", "*\\csrss.exe"))
```

Initially AI created the following rule
```
index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=10 
TargetImage="*\\lsass.exe" 
(SourceImage="*\\procdump*.exe" OR SourceImage="*\\procdump64.exe")
| stats count min(_time) as firstTime max(_time) as lastTime by host, User, SourceImage, TargetImage, TargetProcessId, GrantedAccess, CallTrace
| eval technique="T1003.001 - LSASS Memory Dump"
```
However looking at the code it was assessed to be too limited in scope as this rule only detects when procdump.exe or procdump64.exe is attempting to access lsass.exe.
