# Objectives:

- Create a VM router to enable other connected VM’s to communicate with the internet and home network PC’s
- Learn basic firewall configuration skills within the router.

# Research

The solution that aligned the most with the objectives laid out was a virtual machine running OPNSense. The external interface would be configured to communicate with my home router and the internal interface will be configured to communicate with my devices. The OPNSense router will have a configurable firewall that can isolate machines and restrict incoming and outgoing traffic.

# Implementation

## Setup of Virtualmachine

Using the correct .iso file a virtual machine was configured to run OPNSense. The installation process was relatively frictionless with the external facing IP given within the range of home router IP’s and the internal facing IP given new subnet IP’s. Initial configuration was completed using the command line interface. Once set up an Ubuntu Virtual machine was used to access the web GUI for OPNSense.

## Setup of OPNSense WebGUI From Home PC

Objective: Access the webGUI for virtualised router from home PC

Issues:

1. Static routing from Home PC wasn't put into the routing table so packets were sent external to the internet instead of being sent to the OPNSense router.  
    Solution: Added static routing to PC utilising CMD line interface. Command used was: 

```
route -p ADD 10.10.10.0 MASK 255.255.255.0 192.168.10.99
```

The parameter -p states that this is a persistent route that will continue to operate after reboots.

*Figure 2. Static Routing Implemented*
![](../../Images/RegularImages/Pasted%20image%2020260926184647.png)

2. OPNSense Router Firewall automatically blocking ICMP packets from other networks and traffic from the home PC  
    Sol: Added firewall rule that allowed ALL network traffic to and from the home PC. 

*Figure 3. Network Rule Implemented*
![](../../Images/RegularImages/Pasted%20image%2020260926184704.png)

3. OPNSense WAN Reply-To was activated on the home PC firewall rule which set the final destination of the packets to the Home Router instead of the Home PC

Sol: Navigated to Firewall -> Rules -> WAN under advanced options changed Reply To from default to None.

*Figure 4. Reply To None*
![](../../Images/RegularImages/Pasted%20image%2020260926184723.png)
Outcome: Virtual machines can access the internet and interface with the Home PC.
