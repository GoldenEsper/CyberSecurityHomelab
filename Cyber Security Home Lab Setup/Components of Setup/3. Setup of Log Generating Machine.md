# Planning

## Objective:

Create a virtual machine/container that can simulate an endpoint/server under attack. Logs should be repeatable and have the ability to observe the results within Splunk server.
## Research:

Three main options were identified to create logs: 

1. Windows Endpoint
2. Active Directory Target
3. Container Web Target App
  
Outcome: Windows Endpoint with a Splunk Universal Forwarder installed

# Implementation

## Creation of endpoint:

- First attempt: Metasploit 3 Build
- Objective: Create Metasploit 3 build
- Issues: Broken build script, had to change version numbers, file location references and had broken resource links.
- Outcome: Save time and create Metasploit 3 build once another operational virtual machine that generates logs is created
Second Attempt 
- Objective: Create Windows Virtual machine
- Issues: During creation of Virtual Machine additional drivers required to allow for windows to recognise virtual drives and virtual network devices were not installed on additional virtualized drives. ProxMox also didn't boot to virtualised bootable media without user input during the boot process. As the terminal for the machine was not monitored during early stages of boot this was missed for early attempts of creation.
- Outcome:  Successfully created windows virtual machine within ProxMox environment.
## Installation of Sysmon and Splunk Universal Forwarder

- Objective: Install Splunk universal forwarder to pass system information onto the server and install sysmon for deeper insights into system data
- Issues: After install of splunk universal forwarder only a small amount of data was passed to Spunk server. In addition, information was not being filed into the correct index on splunk server. Upon further investigation inputs.conf file didn't exist within Splunk Universal Forwarders files. This file determines where to collect information and what index to send collected information to. Created new inputs.conf file and defined what indexes to send collected data. 
- Outcome: Windows security and system logs were forwarding correctly, however Sysmon logs not being passed correctly

## Forward Sysmon Data to server

- Objective: Identify why splunk server is not receiving Sysmon data.
- Issues: There were multiple potential points of failure in the logging process. The first item looked into was the Inputs.conf file. The layout of the file was changed multiple times to ensure the issue wasn’t due to the file. During this process it was identified where the logs file is located (see figure 1). Installation of the Windows add-on application within Splunk rectified the issue.
- Outcome: Invoke-AtomicTest worked with simple tests and prerequisites met.
